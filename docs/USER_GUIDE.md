# AI Factory 用户快速上手指南

> 面向第一次拿到安装包、直接双击使用的最终用户。开发者请看 README.md；
> 已知限制与诚实边界见 [docs/KNOWN_LIMITATIONS.md](KNOWN_LIMITATIONS.md)。

## 1. 这是什么

AI Factory 是一个**本地优先的 AI 软件工程工作台**：AI 员工负责干活，
你负责把关。核心规则只有三条：

1. **AI 只能申请，不能自己拍板**——任务流转要过"证据门禁"，缺证据就拒绝，
   并逐项告诉你缺什么。
2. **关键动作要人批准**——高风险操作会出现在"审批"面板，等你点通过/驳回。
3. **全过程留痕**——每一步都写入不可篡改的审计链，可随时查证。

没有云、没有账号体系，所有数据都在你本机。

## 2. 安装与启动（Linux AppImage）

1. 拿到 `AI Factory-0.1.0.AppImage`（约 124MB）。
2. 赋予执行权限（只需一次）：
   ```bash
   chmod +x "AI Factory-0.1.0.AppImage"
   ```
3. 双击运行，或在终端执行：
   ```bash
   ./"AI Factory-0.1.0.AppImage"
   ```

说明：

- 双击需要系统支持 FUSE；若双击无反应，用上面的终端命令看报错，
  或用 `--appimage-extract` 解包后运行 `squashfs-root/` 里的程序。
- 应用启动时会拉起内置后端（127.0.0.1:3100），无需你手动启动任何服务。
- **数据位置**：数据库默认建在**你启动程序时的当前目录**下的
  `./data/factory.db`（单机 SQLite，任务/证据/审批/审计全在里面）。
  想固定位置，可设置环境变量 `DB_PATH` 指向一个文件路径再启动。
- Windows/macOS 安装包需在对应平台上打包，尚未提供。

## 3. 首次启动：你会看到什么

首次启动会自动创建一个**演示项目 "MyApp"** 和一套 **AI 组织**：

- AI PM（需求转成可验证结果）
- Tech Lead（技术交付负责人）
- Coder #01（后端）、Coder #02（前端）
- QA Lead（质量负责人）

这是演示数据，帮你理解界面；真实使用时你可以创建自己的项目。

## 4. 核心概念（用户视角）

| 概念 | 一句话 |
|---|---|
| 任务（Task） | 一件工作，在看板上有状态（待办 → 计划中 → 进行中 → …）。 |
| 证据门禁 | 任务想往下走，必须先交"证据"（比如代码评审记录、测试报告）。证据不够，流转被拒绝，并告诉你缺哪几项。 |
| 审批（Approval） | 关键动作需要人点头。审批面板列出待办事项，你点"通过"或"驳回"，并留下是谁决定的。 |
| Needs Human | 需要人关注的事项列表（只读）：AI 遇到拿不准的情况会在这里留言。 |
| 审计链 | 所有操作的可验真记录，防篡改、防调序、防删除。 |

## 5. 面板导览

顶部有一排面板标签，日常最常用的是这几个：

- **Dashboard**——总览：交付数、运行中的 Agent、实时动态。
- **Board**——任务看板。**拖拽卡片跨列 = 发起流转**：若证据门禁拒绝，
  会弹出提示告诉你缺什么证据；若你没有该任务的授权，会看到红色
  403 提示（这是正常的权限保护，不是 bug）。
- **Approvals**——待你审批的事项：点"通过"/"驳回"，决定会记录审批人。
- **NeedsHuman**——需要你关注的留言列表（只读），处理完到对应地方操作。
- **Dispatch**——人工派发队列：给任务指定负责人/授权。
- **Models**——模型注册表：各模型供应商、能力、可用状态。
  当前只有 Codex 适配器是真实实现（需你自己登录 Codex 账号）；
  其他供应商为演示占位，不会产生真实调用。

其他面板（Git、QA、CI/CD、Skills、Memory、MCP、Knowledge、Evaluation、
Agents、Activity、Events、Report、Terminal、Editor 等）面向进阶用法，
可在使用中逐步探索。

## 6. 一个最简使用流程

1. 打开 **Board**，看演示任务的当前状态。
2. 试着把一张卡片拖到下一列：
   - 若被拒绝，toast 会列出缺少的证据——这就是"证据门禁"在工作。
   - 若提示 403，说明该任务需要授权——去 **Dispatch** 看授权情况。
3. 打开 **Approvals**，处理一条待审批事项，点通过/驳回。
4. 打开 **NeedsHuman**，看 AI 留了什么需要你关注的事项。

## 7. 数据与备份

- 全部数据在 `factory.db` 这一个 SQLite 文件里（位置见第 2 节）。
- 备份 = 停服后复制这个文件；恢复 = 替换后重启。
- 应用内也有备份功能（Ops/备份相关面板），备份带完整性校验。
- 详细操作见 [docs/backup-restore-guide.md](backup-restore-guide.md)。

## 8. 诚实边界（先说清楚）

- **Codex 真实调用需要你自己登录**：在机器上执行 `codex login --device-auth`
  完成登录后，Codex 适配器才能真正干活；未登录时状态会如实标注，
  不会伪造成功。
- **除 Codex 外的模型供应商是演示占位**，不会消耗额度也不产生真实结果。
- **无真实隔离环境**：AI 工具在本机直接运行，请勿让它执行你不放心的操作；
  工具白名单默认全拒（fail-closed）。
- 仅在 Linux 验证过；Windows/macOS 包、三平台签名均未提供。
- 完整清单见 [docs/KNOWN_LIMITATIONS.md](KNOWN_LIMITATIONS.md)——
  建议使用前花五分钟读一遍。
