# 治理层可见性演示脚本（10 分钟，文案先行版）

> 定位：本文件是第三轮 V3.0 审计 Top 10 第 9 项“治理单列一层”的文案三件套之一（演示脚本）。
> 边界：本脚本演示的是**文案与已有能力**，不是新视图。视图部分门控于客群判定（Tan 定团队治理），脚本中凡涉及视图均以“未来视图位置”表述，不得假装视图已存在。
> 闭环要求（审计 #9 成功标准）：演示必须走通“策略改动 → 审计留痕 → 成本变化”的闭环，缺一环即不宣布完成；客群未定前不得为治理层编定价。

## 演示总览（10 分钟）

| 段 | 时间 | 讲什么 | 预期结果 |
|---|---|---|---|
| 0. 开场定调 | 1 分钟 | 治理层是什么：审计 + 策略 + 成本拼成的一层，不是三个散落的设置页 | 听众能复述“审计留痕、策略可改、成本可控”三句话 |
| 1. 策略改动 | 3 分钟 | 改一条预算上限 / 改一次扩展信任决定 | 改动即时生效且有据可查（见步骤 1–2） |
| 2. 审计留痕 | 3 分钟 | 在审计链里找到这次改动的事件 | 事件可查、含 id 与计数、不含敏感值（见步骤 3） |
| 3. 成本变化 | 2 分钟 | 触发一次警告 / 熔断 / 放行，成本视图状态随之变化 | 状态从 ok → warned → tripped → released 全程可见（见步骤 4） |
| 4. 收尾与诚实边界 | 1 分钟 | 未定项与占位项一次讲清 | 听众知道什么是已落地、什么是未定、什么是占位（见步骤 5） |

## 步骤 0：开场（讲什么）

讲稿：

> “AI Factory 的治理层不是一个新引擎，是三块已有能力拼成的一层：审计链负责留痕，策略层负责定规则，成本层负责控 spend。今天演示一个闭环：改一条策略，审计里立刻有记录，成本视图的状态跟着变。”

不要讲的话：不要说“治理层已上线为独立面板”（无新 tab）；不要说“支持团队治理售卖”（客群未定）；不要报任何价格。

## 步骤 1：改一条预算上限（点哪里、看到什么）

- 点哪里：Ops 页签内的 BudgetPanel（既有面板，非新视图）。
- 做什么：为当前项目新建或修改一条预算（例如 project 级、usd-estimate、monthly）。
- 看到什么：预算行出现范围 / 单位 / 周期 / 上限 / 本窗口用量 / 状态；上限校验 fail-closed（零 / 负 / 无穷上限拒绝写入）。
- 预期结果：预算行状态为 ok；若改的是已存在同范围 + 同键 + 同单位 + 同周期的预算，apply-defaults 不覆盖——演示时如遇此情况要如实讲出，不硬改。

## 步骤 2：改一次扩展信任决定（点哪里、看到什么）

- 点哪里：扩展面板的信任决定入口（既有面板）。
- 做什么：对一个未签名 bundle 作一次显式信任决定（或取消信任）。
- 看到什么：决定按 bundle 哈希键控记录在 trust.json；bundle 一改即失效，需重新决定；签名无效的 bundle 安装被拒绝（fail-closed）。
- 预期结果：决定落盘且可在信任列表中看到；同时讲清：vm 沙盒不是安全边界，信任模型只解决来源可审计 + 显式决定。
- 诚实插入：讲到默认门禁时必须说：“默认门禁策略目前是**默认语义未定**（拒绝 vs 警告确认，待决策），本次演示用的是显式逐次决定，不是默认策略。”

## 步骤 3：在审计链里找到留痕（点哪里、看到什么）

- 点哪里：审计链 / 审计导出入口（既有能力）。
- 做什么：检索步骤 1 与步骤 2 对应的审计事件；导出一份诊断包（可选，operator + confirm:true）。
- 看到什么：事件含 id 与计数、不含密钥与敏感值；诊断包只含计数与 stripped 字段，序列化自检命中密钥即 409 不发货。
- 预期结果：两次改动各有对应事件；诊断包能讲清“为什么只含计数”（隐私合规明示）。

## 步骤 4：触发成本变化（点哪里、看到什么）

- 点哪里：同一 BudgetPanel；用量侧用模拟 / 手动记录（当前无真实模型回执，不得伪造 provider-reported 行）。
- 做什么：把用量推到 80% 以上，再推到 100%，随后做一次带理由的放行。
- 看到什么：80% 警告一次（warned，不阻止调用）→ 100% 熔断（tripped，新调用被拒绝，已在运行的确定性工作不受影响）→ 放行后状态为 released，且上限数值不变。
- 预期结果：听众能说出三句话——“警告不拦调用、熔断只拦新调用、放行不提高上限”。
- 诚实插入：讲到数字时必须说：“当前用量是模拟 / 手动记录，不是真实账单；换算表全部 measured: false，系数是占位，待真实模型接通后实测填数。”

## 步骤 5：收尾——诚实边界一次讲清（讲什么）

按顺序讲清四项，不得跳过：

1. 已落地：审计链、成本治理策略层、扩展信任模型、出站防火墙、run 元数据持久化（200 条 / 90 天）。
2. 未定：扩展信任默认门禁（#6 二选一）、客群（单人提效 vs 团队治理）、治理层定价（不编）。
3. 未接通：云端行（门控于 #1 Codex 真实 turn 实证）；演示中云端区如被问起，出示显性空态文案“尚未接通”，不得用本地行冒充。
4. 占位：成本换算系数、模型出境文案（除 Codex 外适配器仍是 stub）。

收尾句：

> “所以治理层今天能演示的是闭环本身：策略可改、改动留痕、成本可控。视图形态与团队治理的售卖，等客群判定之后再建。”
