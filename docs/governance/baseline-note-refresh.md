# 基线注记刷新机制（R7 #8 落盘，治理文档落点）

## 问题

R5→R6→R7 三轮同一模式：每轮本地 main 基线前进一步，文档注记落后一轮。
只改数字不改机制，下一轮还会再来一轮。本机制是 R7 #8 的修复本身，
不是附录：此后每个代码侧收口提交必须含“基线注记刷新”检查项。

## 收口清单项：基线注记刷新

收口人按表逐项打勾，或显性标“内容未变、注记已刷”。缺一即该收口的
文档保真项未完成，不得宣称“文档注记已同步”。

| # | 文档 | 刷新内容 |
|---|---|---|
| 1 | `docs/verification/tab-inventory.md` | 表头基线 + 复核日期 + 刷新记录；计数复核、旧别名 grep、占位符比对四项全重跑，只改数字不跑比对视为未刷新 |
| 2 | `docs/rules-priority.md` | H1 与正文基线一致；引擎在基线间零改动须以 git diff 核对，不得只改标题 |
| 3 | `docs/governance/metering-disclosure.md` | 页首三项（口径日期、基线注记、复核依据），由当轮 #7 同步刷新，本机制只保证基线数字不分裂，不得两处各写一套基线 |

| 5 | `docs/governance/acp-extension-hosting-pointer.md` | 复核节：主本一致性 + 三包时效引用（acp 命中、demo 数、真实第三方扩展数、触发门状态） |
| 6 | `docs/local-channel-spike-pointer.md` | 复核注记：指针与主本一致性 + 四条件状态 + 本地适配器 grep |

## 细则

- 指针页与主本的同步责任引用既有约定（修订只改主本，指针页随后同步
  状态行），不重立；主本结论不得在本机制文档里重写第二套。
- 披露页与设计稿的口径同步仍由当轮计量项负责，本机制只保证基线数字
  不分裂。
- 刷注记不得删键、改占位符名、改主本结论或改决策单状态，违者视为未刷新。
- 失败降级形态：包未完成时不得宣称“盘点表基线已对齐”或“文档注记已同步”，
  未刷新项本身就是交付清单中的未闭合行。
