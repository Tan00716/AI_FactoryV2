# 限流公平性设计稿（设计，未接线）

- 状态：设计稿，非实现。限流 enforcement 在本设计稿阶段**不接线**；任何读到本文档的人不得据此宣称“限流已上线”。
- 基线：本地 main ce9ff66（R4 审计基线）。
- 适用主体：**单人自限**——Tan 对自己的预算自限，不是多用户 / 多租户之间的公平分配。未来多用户场景须另立设计，本稿不覆盖。
- 依据：R4 审计 TOP10 第 9 条；R3 #9 治理文案三件套（docs/governance/policy-list.md、cost-view.md）；R3 #8 本地模型通道核查结论（不通过）；R4 #3 信任门禁二选一（未决策，默认 fail-closed）；R4 #5 计量披露页（兄弟任务进行中）。
- 口径一致要求：本文档的计量口径须与 R4 #5 计量披露页一致。同一数字在两处不得有两种说法。若 #5 披露页落地后的口径与本稿有出入，接线评审时以披露页为准并修订本稿，不得直接按本稿接线。
- 复核点：本稿**有效期至计量实报接通评审时**。过期须复核，不得直接当成接线依据；复核时须重对实报口径、本地通道状态、信任决策三项。
- 证据等级说明：竞品参照按 R4 审计标注（Codex 完成轮次规则为官方直读；Zed 仅采纳计费、Cursor 封顶为次级复核）；自身现状为本轮代码现测（见第 0 节）。

## 0. 现状锚点（设计依据，非设计内容）

- quota 引擎现状（packages/quota/src/budget.ts，现测）：80% 警告一次 / 窗口；100% 熔断，熔断后拒绝**新**模型调用；熔断每窗口可释放一次，释放只清熔断、永不提高上限。
- 计量输入现状：quota 默认行与 CommandPanel 预算行均为估算（estimated），除 provider-reported 外无实报输入。估算行现状见 R3 #9 cost-view.md。
- 本地通道现状：R3 #8 核查结论为不通过——无可执行本地适配器、无 endpoint 配置与探针、adapter.invoke 未接 egress。本地降级分支因此在今天不可用（见第 4.3 节）。
- 信任决策现状：R4 #3 二选一（拒绝 vs 警告确认）未决策，未决策期间默认 fail-closed。

## 1. 计量输入前提（接线前置条件）

- 设计：限流 enforcement 的唯一合法输入是 provider-reported 实报计量。实报接通前，限流保持“设计稿 + 不接线”状态。
- 依据：估算数字的误差无法追溯；对估算数字执法等于把估算误差放大成用户损失（R4 #9 根本原因）。
- 未决策点：无。本节为硬性门控，不设例外分支。
- 禁止的降级形态：实报未接通时不得降级为“对估算数字接软限流”；估算超限提示不得写成账单口径，提示文案须带 estimated 标记（与 #5 披露页同口径）。

## 2. 触发点：轮次边界，非轮次中间

- 术语定义（本稿内有效，接线评审时复核）：
  - 轮次：用户一次请求触发的模型调用链，含该链内的工具调用与重试，以模型最终回复交付或明确失败为边界。
  - 建议：模型产出中可供用户采纳的单位（如一段代码修改、一份文本建议）。
  - 采纳：用户明确接受 / 应用建议的行为。
- 设计：
  - 触发检查点只设在轮次边界：新轮次启动前检查预算状态；轮次进行中不做中途拦停。
  - 轮次中间超限：**完成当前轮次**，不丢半成品；拦停只作用于下一个新轮次。参照 Codex 完成当前轮次再限流（官方直读）。
  - 80% 警告：沿用现有 warn-once 语义，警告一次 / 窗口，不重复打扰；警告文案须含当前用量、阈值、计量口径（estimated / reported）与超限后行为。
  - 100% 熔断：熔断后新轮次启动被拒绝，拒绝文案须显性写清原因（预算、阈值、窗口）与恢复条件（窗口重置 / 手动释放），不得静默失败。
- 依据：轮次中间拦停会丢半成品，是公平性损失最大的拦停形态；现有引擎的“拒绝新调用”语义与轮次边界天然对齐，只需在设计层面把“新调用”明确为“新轮次”。
- 未决策点：轮次内多模型调用链的边界细节（如一次轮次内模型自我重试是否算新调用）留接线评审时按实际调用链复核，本稿不预设。

## 3. 计费粒度：仅采纳计费，建议与采纳分开记

- 设计：
  - 建议与采纳分开记账：模型产出的建议先记为“建议量”，用户采纳后才记为“计费量”；预算阈值只对计费量执法。
  - 未被采纳（忽略、拒绝、未处理）的建议不计入计费量。参照 Zed 仅按采纳计费（次级复核）。
  - 采纳的判定以用户明确接受 / 应用为准；系统不得以“已展示”或“已生成”代替采纳。
- 依据：只对用户认可的产出收费，是公平性的第二条支柱；否则用户会为看不上的输出买单。
- 未决策点：
  - 自动应用的输出是否算采纳：本稿默认**不算**（只算用户明确接受 / 应用），接线评审时若产品引入自动应用路径，须另行决策并修订本稿。
  - 建议量的展示位置（是否在 UI 单独列示）留接线评审时定，本稿只要求建议量与计费量不得混在一行数字里。

## 4. 超限后行为：完成当前轮次、显性提示、默认二选一

### 4.1 通用行为（两种默认选项共有）

- 完成当前轮次（第 2 节），显性提示（原因、阈值、窗口、恢复条件），审计留痕（第 5 节）。
- 超限后不得静默降质：任何降级行为都须显性告知用户，且用户可查到降级前后的档位变化。

### 4.2 默认选项 A：暂停（本稿推荐的默认选项）

- 语义：熔断后停止一切新轮次启动，直至窗口重置或用户手动释放；已完成轮次的成果与数据完整保留；不启动任何替代模型路径。
- 取舍：优点是语义最简单、无降质误读、无额外依赖；缺点是用户在预算耗尽后完全停摆，恢复只能等窗口或手动释放。
- 与信任决策的同口径：R4 #3 未决策 = fail-closed；本稿默认选项与之同口径——**未决策期间默认暂停**，不得默认付费续跑，不得默认静默放行。

### 4.3 默认选项 B：本地降级（现阶段不可用的备选）

- 语义：熔断后新轮次改走本地模型或更低档位模型；档位变化须显性告知；本地路径的用量计量口径须在披露页中单独说明（本地用量是否计入同一预算，留接线评审时定）。
- 取舍：优点是预算耗尽后仍可继续工作；缺点是产出质量可能下降，且用户可能误以为仍在用原档位模型。
- 可用性约束（诚实条款）：本地降级以本地通道可用为前提。R3 #8 结论为不通过，R4 #1 本地 spike 尚未立项，因此**今天选 B 等于先接受本地通道门控**；在本地通道通过实证前，B 不得作为默认选项，只能作为评审时的备选记录。
- 未决策点：降档位的具体档位表、本地用量是否计入同一预算，均留接线评审时定。

### 4.4 付费续跑：只留占位，不写实现

- 占位内容仅此一节：未来若产品引入计费，超限后可设“付费续跑”分支；其启用前提是真实计费存在且费率已披露。
- 现阶段约束：付费续跑**不作默认选项、不参与默认决策**；不得在超限提示中出现付费入口、价格或购买引导；不得以任何形式暗示用户“付费即可继续”。
- 未决策点：全部。费率、支付方式、续跑额度、退款规则均未决策，本稿不写。

### 4.5 替代方案：不执法、只披露 + 预算提醒（平行选项）

- 内容：不限流 enforcement，只做 #5 披露页 + 预算提醒（80% 警告、100% 提醒，不拒绝新轮次）。
- 地位：与 4.2 / 4.3 平行的选项，由 Tan 在设计稿评审时定，不在本稿内预选。
- 取舍：优点是零误拦风险；缺点是预算自限失去强制力，超支只能靠用户自觉。

## 5. 审计记录要求

- 每次拦停（拒绝新轮次、警告、熔断、释放）须留痕，缺一不可：
  - 何时：事件时间（窗口标识一并记录）。
  - 因何阈值：触发的预算、范围（task / person / project）、阈值（80% / 100%）、当时用量与上限。
  - 轮次是否完成：拦停发生时进行中的轮次是否已完成交付（是 / 否 + 轮次标识）。
  - 计量口径：当时用量是 estimated 还是 provider-reported（实报接通前恒为 estimated）。
  - 开关状态：当时生效的默认选项（暂停 / 本地降级 / 只披露）与信任门禁状态。
- 审计记录只记上述元数据，不记模型输出原文与用户请求原文；审计链路复用现有审计链，不新建立账本（接线时复核）。
- 未决策点：审计事件的命名与存储字段细节留接线时按现有审计链约定定，本稿只定“记什么”，不定“怎么记”。

## 6. 回滚 / 关闭方式

- 接线前（当前状态）：回滚即不接线。本稿本身不产生任何运行时行为，删除本稿不影响产品。
- 接线后回滚：关闭 enforcement 开关，回到“只披露 + 预算提醒”模式（4.5 节）；已发生的熔断与释放记录保留在审计中，不删除、不改写；关闭操作本身须进审计。
- 关闭的触发条件：实报口径被证伪、本地降级档位误导用户、或 Tan 决策关闭；三者任一成立即应关闭 enforcement 并回到披露模式，关闭决定不须等待下一轮审计。
- 未决策点：关闭开关是否走信任门禁，留接线评审时与 R4 #3 决策交叉核对（第 7 节）。

## 7. 与信任决策（R4 #3）的交叉核对

- 限流开关是否走信任门禁：本稿记录为**待交叉核对项**，接线评审时须与 #3 决策结果对照。
- 在 #3 未决策期间：限流开关相关操作一律按 fail-closed 处理——即默认暂停（4.2 节），不得以“限流开关不走门禁”为由绕过默认暂停。
- 若 #3 决策为警告确认：限流默认选项须重审——警告确认是否适用于“超限后继续”这一确认场景，须在接线评审时另行决策，本稿不预设警告确认可直接套用。

## 8. 三场景走查（唯一答案，第三人可复核）

| 场景 | 设计稿答案 |
|---|---|
| 轮次中间超限 | 完成当前轮次，不丢半成品；拦停只作用于下一个新轮次；提示写清原因、阈值、窗口、恢复条件；审计记“轮次已完成”。 |
| 建议未采纳 | 建议量与计费量分开记；未采纳建议不计入计费量；阈值只对计费量执法；自动应用输出默认不算采纳。 |
