## 二、策略清单

### G-1 审计留痕策略

- 策略：一切治理相关动作（预算熔断与放行、信任决定、审计导出、run 历史清除）必须进审计链；审计事件只记 id、计数与键名，不记密钥与敏感值。
- 谁可改：审计链本身为 append-only，不提供改写入口；导出与清除走 operator 角色确认。
- 改动是否进审计：是。清除类动作记审计事件（如 TASK_RUN_HISTORY_CLEARED 仅记条数）；审计导出记包 id 与章节计数。
- 当前状态：已落地。

### G-2 成本预算与熔断策略

- 策略：三级预算（task / person / project）× 三单位（usd-estimate / calls / tokens-estimate）× 四周期（daily / weekly / monthly / all-time）；80% 警告一次，100% 熔断拒绝新调用；放行理由必填、只清本窗口、永不提高上限。
- 谁可改：预算对象由 operator / 项目方配置；放行需理由并记审计。
- 改动是否进审计：是（放行理由与熔断事件进审计）。
- 当前状态：已落地。口径细节见《成本视图文案》。

### G-3 扩展信任策略

- 策略：宿主 API v1 冻结；签名有效 + 官方密钥 = official 自动信任；签名有效 + 其他密钥 = 自动信任；签名无效 = 安装拒绝（fail-closed）；未签名 = 需显式信任；信任决定按 bundle 哈希键控，bundle 一改即失效；信任文件损坏则决定作废、不崩溃。
- 谁可改：信任决定由用户显式作出并记录在 trust.json；单人例外语义待 #6 决策（见 G-6）。
- 改动是否进审计：是（信任决定由路由层记审计）。
- 当前状态：已落地；vm 沙盒不是安全边界，信任模型只解决来源可审计 + 显式决定。

### G-4 出站防火墙策略

- 策略：缺文件默认 = enabled + deny + factoryDefault；向导模板显式放行；开发态显式 OFF 记审计；不防 DNS rebinding（UI 明示）。
- 谁可改：向导完成时 note-stamped 合并；存量 legacy 文件规则原样保留。
- 改动是否进审计：是（开发态 OFF 记审计）。
- 当前状态：已落地。

### G-5 诊断包与隐私策略

- 策略：诊断包只含计数与 stripped 字段；审计 details 不读入包、任务证据只有计数、环境变量名与值不进包、不上传；序列化包自检命中密钥即 409 不发货。
- 谁可改：导出需 operator 角色 + confirm:true。
- 改动是否进审计：是（DIAGNOSTICS_EXPORTED 只记包 id 与章节计数）。
- 当前状态：已落地。模型出境一节为占位文案（除 Codex 外适配器仍是 stub）。

### G-6 扩展信任默认门禁策略

- **当前状态：默认语义未定。**
- 待决策项（审计 #6）：默认策略二选一——拒绝 vs 警告确认；单人例外语义为逐次确认 + 进审计、无全局开关。
- 在决策记录落地前，本层只能展示“默认语义未定”，不得编造一个默认策略，也不得把信任模型的现有裁决规则说成默认门禁。

### G-7 云端行可见性策略

- 策略：指挥屏 / 可见性层的云端行严格门控于审计 #1（Codex 真实 turn 实证）成功；#1 未成功前云端区为显性空态，写明尚未接通，不得静默缺失，不得用本地行冒充。
- 当前状态：未接通（#1 未完成）。演示时云端区必须出示空态文案，不得跳过。
